# Exergism v0.1.0 adversarial pre-release review

Date: 2026-08-17
Target: `release/exergism-0.1.0-hardening`
Scope: canonical corpus boundary, formal model, schema/IDs, derived ontology, licensing, governance, release mechanics, and downstream ECL separation.

## Review rule

This review treats the recovered philosophical and formal corpus as the semantic baseline. It may identify ambiguity, inconsistency, or underspecification, but it MUST NOT silently repair doctrine by inventing values or rewriting canonical source material.

## Findings

### EXR-001 — Transition immediate-ethics weights sum to 0.90 — P1

The recovered `modulacion_por_contexto.transicion.pesos` profile defines `a1..a5` values whose sum is `0.90`, unlike comparable weight groups that sum to `1.00`.

**Risk:** an implementation may silently renormalize the weights or invent the missing `0.10`, producing numerical results that are not actually specified by the recovered model.

**Disposition for v0.1.0:** exposed, bounded, not doctrinally repaired. `formal/FORMAL-MODEL-STATUS.md` records the issue and repository validation fails if the recovered values are changed without an explicit semantic decision.

### EXR-002 — Macroevent aggregation uses unbound `z1` / `z2` — P1

The recovered macroevent formulas reference `z1` and `z2`, but the canonical model does not assign values to them.

**Risk:** consumers can obtain incompatible outputs by silently choosing defaults.

**Disposition for v0.1.0:** exposed, bounded, not doctrinally repaired. Consumers MUST NOT silently default these parameters. Numerical use of the affected formulas requires an explicit parameter profile.

### EXR-003 — Prior CI did not independently prove generated ontology freshness — P2

The initial workflow invoked the repository validator, which itself compares generated OWL with the checked-in projection, but it did not make the regeneration/diff boundary independently visible in CI.

**Fix:** CI now regenerates `ontology.owl` and executes `git diff --exit-code -- ontology.owl` after validation.

### EXR-004 — Corpus and tooling had no explicit public license boundary — P1

The initial public snapshot stated that no public-content license had been selected.

**Risk:** public visibility could be mistaken for permission to reproduce/adapt, while contributions could arrive under unclear terms.

**Fix:** corpus/data/documentation are mapped to CC BY-SA 4.0; repository tooling/schema are mapped to Apache-2.0; no copyright assignment is required merely to contribute; ECL is explicitly not inherited.

### EXR-005 — “Canonical” could be misconstrued as an authority claim — P2

A canonical maintained lineage can be confused with an assertion that maintainers possess exclusive authority over philosophical truth.

**Fix:** `GOVERNANCE.md` defines canonicality procedurally. Forks, criticism, competing interpretations, and independent continuations remain legitimate; administration is custodial rather than a permanent doctrinal veto.

### EXR-006 — Release-manifest self-reference could make hashing ill-defined — P2

Embedding a release manifest containing its own digest inside the canonical digest set would create avoidable self-reference.

**Fix:** `scripts/build_release_manifest.py` deterministically inventories and hashes canonical source/derived artifacts from an exact checkout and emits the release manifest as a release artifact outside that digest set.

### EXR-007 — Derived ontology could leak downstream ECL governance semantics — P1

Because ECL historically carried Exergism-derived concepts, an ontology generator could accidentally grow legal/governance classes and collapse the conceptual/application boundary.

**Fix:** documentation states the boundary and validation rejects known downstream ECL terms including `RestrictedParty`, `GovernanceDecision`, `ECLCriterion`, and `ScheduleEntry` from `ontology.owl`.

### EXR-008 — Preserved historical examples are not fully reproducible pipelines — P2

The recovered Iran and Kabul examples preserve data/visualizations, but the original scripts for every generated visualization were not recovered.

**Risk:** users may mistake preserved outputs for a fully reproducible computational pipeline.

**Fix:** documentation and release notes describe them as preserved applied-analysis artifacts, not as complete reproducible pipelines.

## Additional checks

- All canonical JSON documents parse and validate against schema v2.
- Canonical node IDs and canonical IDs are unique; `concept_ref` values resolve.
- `source_path` values are unique within each canonical source file.
- The four-book architecture is present and numbered exactly 1–4.
- Required formal variables and formula symbols are present.
- `ontology.owl` is well-formed XML and regenerates byte-for-byte from canonical inputs.
- No canonical philosophical source, book definition, formal-model source, example data, symbol, schema, or generated ontology was semantically modified by this hardening tranche.
- ECL remains downstream: no Exergism score or ontology assertion automatically produces an ECL restriction, Schedule designation, or governance outcome.

## Release assessment

EXR-001 and EXR-002 remain open **formal-model specification questions**, but they do not prevent publishing v0.1.0 as the first faithful, auditable baseline because v0.1.0 explicitly records that those calculations are under-specified and forbids silent defaults. They MUST be resolved through an explicit later semantic change before any claim of a fully calibrated formal-model 1.0.

No unresolved finding in this review requires altering the recovered semantic baseline before v0.1.0.
